## 2. 数值采样：曝光 vs 时间（关键 bug）

默认相机位（东南角望北墙），关闭自动曝光锁定 `exposure = 1.0`，实测：

| 时间 | 太阳高度角 | sunInt | getAverageLuminance | getToneMappingExposure |
|------|---------|--------|--------------------|----------------------|
| 0:00 | -26.9° | 0 | 1.22 | **0.14** |
| 6:00 | 13.9° | 0.84 | 1.20 | **0.14** |
| 9:00 | 43.6° | 2.42 | 1.14 | **0.14** |
| 12:00 | 64.8° | 2.91 | 1.21 | **0.14** |
| 15:00 | 43.6° | 2.42 | 1.19 | **0.14** |
| 17:45 | 23.6° | 1.29 | 1.14 | **0.14** |
| 18:30 | 23.5° | 0.84 | 1.20 | **0.14** |
| 19:00 | 4.1° | 0.47 | 1.24 | **0.14** |
| 21:00 | -14° | 0 | 1.21 | **0.14** |

**结论**：所有时刻 `lum ≈ 1.2`，`targetLuminance / lum = 0.17 / 1.2 ≈ 0.14`
**中午和夜晚完全同一个 exposure**。P9 修好了采样（> 0），但
`targetLuminance = 0.17` 的算法假设错了——0.17 是 sRGB 中间灰，
对应的 linear 约 0.024，而 HDR 场景采样值全是 1+ 量级。
等于算法被告知"把线性亮度压到 0.024"，必然全场景暗成夜晚。

**P9b 规格已记录此 bug 并给出修复方案**（分档曝光：白天锁定 1.0，夜晚 0.5，过渡插值）。

## 3. 天空颜色 vs 时间（采样正确，但被曝光压死）

采样 `scene.background` 与 elevation，关键帧映射正确：

| 时间 | elevation | background (linear) | 视觉预期 |
|------|-----------|--------------------|---------|
| 0:00 | -26.9° | (0.002, 0.003, 0.007) | 深夜蓝黑 ✅ |
| 6:00 | 13.9° | (0.028, 0.038, 0.088) | 黎明蓝灰 ✅ |
| 12:00 | 64.8° | (0.347, 0.558, 0.807) | **正午浅蓝** ✅ |
| 17:00 | 23.6° | (0.046, 0.074, 0.152) | 傍晚蓝灰 ✅ |
| 18:00 | 13.9° | (0.028, 0.038, 0.088) | 黄昏蓝紫 ✅ |
| 21:00 | -14.2° | (0.002, 0.003, 0.007) | 深夜蓝黑 ✅ |

**背景色是正确的**。但 vision 分析 12:00 截图时判"窗外是深蓝色夜空"——
因为 exposure 0.14 把 background 的 linear (0.347, 0.558, 0.807)
经 ACES + toneMappingExposure 后压成接近黑夜的暗蓝色。

**结论**：skyColors 关键帧没问题，是 P9b 曝光 bug 造成的错觉。

## 5. 性能观测

- 本环境 FPS 稳定在 **4.7**（HUD 读数）
- 1440×900 视口，`draw calls = 1`（composer pass 数）
- 阴影贴图 2 张（1 directional + 1 spot，P9 收敛预算已生效）
- **无法在本环境验证 P9 的 30 FPS 目标**——SwiftShader 下 rAF 不派发，
  5 FPS 是渲染耗时而非稳态帧率。用户在真实 GPU 机器上跑才能看到。

## 6. UI 层面发现（小 bug）

- WebGPU 降级提示挂在左上角，红色错误样式。WebGL2 已工作，这条是常态不该红色
- 时间轴药丸显示「17:45」，但通过 `engine.setHour(21)` 改时间后 3D 视图更新了而药丸没更新——
  **这不是 bug**：Hermes 绕过了 React state 直接调 engine。真实用户拖时间轴时
  `handleAxisHourChange` 会同步 `setTimeValue` 与 `engine.setHour`，两者保持一致
- 照度估算 31%/35% 偏低，可能是估算算法保守，也可能是曝光压暗了实际画面
- HUD「三角形 66」数字普通用户看不懂（P10 处理）

## 7. 决定

- **不合并 P9 现状**：曝光 bug 导致白天黑夜一个样，视觉比 P9 之前更糟
- **写 P9b 规格**（已完成，`docs/P9b-exposure-godrays-spec.md`）：
  - 曝光分档（白天 1.0 / 夜晚 0.5 / 过渡插值）
  - godrays 加 `uBoost` uniform（默认 3.0）放大输出
  - lightShaft opacity 从 0.28 → 0.6，分母 π/4 → π/6
  - godrays 默认参数 density 0.2→0.5、weight 1.0→2.0
  - WebGPU 提示从红色警告改成灰色 info
- **不动 bloom strength / threshold / radius**（P9 好不容易修好的窗洞白，别改回去）
- **P10 UI 视觉统一等 P9b 落地后再写规格**
