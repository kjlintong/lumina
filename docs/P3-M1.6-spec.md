# Lumina P3 — M1.6 交互闭环 实施规格

> 这是交给 Claude Code 执行的规格。先读 `CLAUDE.md`（工程铁律与红线），再读本文件。
> 现状：`npm run verify` 全绿（166 测试）。本轮**不得破坏**任何既有测试。

## 目标（M1.6 验收判据，工程方案 §1.2）

把现有的纯逻辑模块（`binding.ts` / `sceneSystem.ts` / `illuminance.ts` / `zoneTypes.ts`）真正接进 UI 与渲染引擎，做成可交互闭环：

1. **活动区增删改**：新建/重命名/改类型/删除活动区，**删除区不级联删除灯具**（ADR-01）。
2. **单灯全参数控制**：选中一盏灯，调位置 / 姿态 / 亮度 / 色温 / 配光参数。
3. **可选绑定**：手动移动灯具 → 自动解绑（ADR-02）；区移动/旋转 → 绑定灯跟随（ADR-13）。
4. **user-locked 保护**：用户手动改过的字段不被场景预设覆盖（ADR-17）。
5. **场景切换真的改灯**：点"观影"，灯真的变暗变暖。
6. **照度面板**：显示各活动区相对照度 + **必须带红线标注**「相对估算，非实测照度」（§6.3 / ADR-15）。

## 关键现状缺口（必须先补，否则 UI 改了灯画面不变）

### 缺口 1：SceneEngine 没有 `updateFixture`
`src/scene/sceneEngine.ts` 只有 `addFixture` / `removeFixture`。现在改了 `Fixture` 的任何字段，Three.js 光源**不会**更新。必须新增：

```ts
updateFixture(fixture: Fixture): void
```
- 若该灯已存在 → **重建**：从场景移除旧 `object`，用 `buildLightFromFixture` 重新构建，把新 `object` 加回场景，更新 `fixtureLights` Map。
  （重建比原地改属性简单可靠；重建后必须重新记录该灯的 `baseIntensity`，见缺口 2。）
- 若不存在 → 等价 `addFixture`。

### 缺口 2：场景级别从未应用到实际灯光（最关键）
现在引擎 `addFixture` 只把 `candela`（= lumens/4π）一次性写进 `light.intensity`，**`control.sceneLevels` 完全没有被用来调制实际灯光**——这是「点观影灯不变暗」的根因。

要求：
- 引擎给每个 `fixtureLights` 条目记录 `baseIntensity`（该灯未调光时的原始强度，即 `buildLightFromFixture` 返回的 `light.intensity`）。
- 新增 `setFixtureLevel(fixtureId: string, level: number): void`：把 `light.intensity = baseIntensity * clamp(level, 0, 1)`。
- `updateFixture` 重建后必须重记 `baseIntensity`，**然后再应用当前 level**（否则重建会把亮度重置成全亮）。
- 若一个 `Fixture` 的 `control.sceneLevels[activeSceneKey]` 有值，引擎应以该值作为 level 应用（这样切换场景后重建过的灯不会丢状态）。

### 缺口 3：Zustand + Immer store 根本不存在
工程方案钦定 Zustand 5 + Immer 10，但 `package.json` 里依赖在了，`src/` 里**没有任何 store**，`App.tsx` 还在用 `document.getElementById` 命令式操作。本轮必须建立真正的 store，并让 App 从 `getElementById` 迁移到 React 组件。

## 架构：数据流单向

```
用户操作 React 面板
   ↓ 调 store action（immer produce 不可变更新 project）
useProjectStore（Zustand 5 + immer）
   ↓ 订阅 store（transient subscribe，不触发 React rerender）
SceneEngine（重建/更新 Three.js 光源 + 太阳 + 渲染循环）
```

渲染层与业务状态分离（工程方案 §3.1 / CLAUDE.md 既有约定）。store 是唯一权威数据源，引擎是渲染投影。

## 交付物

### 1. `src/store/projectStore.ts` — Zustand 5 + Immer store（新建）

状态：
```ts
interface ProjectState {
  project: LuminaProject;          // 唯一权威数据
  selectedFixtureId: string | null;
  selectedZoneKey: string | null;
  activeSceneKey: string | null;
  sceneTransition: { startedAt: number; durationMs: number; key: string } | null;
  // actions（全部用 immer produce 做不可变更新，纯函数来自 binding.ts）
  addZone(type: ActivityZoneType, pos: readonly [number, number], name?: string): string; // 返回 zoneKey
  removeZone(zoneKey: string): void;        // 调 binding.removeZone（不级联删灯）
  renameZone(zoneKey: string, name: string): void;
  changeZoneType(zoneKey: string, type: ActivityZoneType): void; // 调 binding.changeZoneType + zoneTypes 模板
  moveZone(zoneKey: string, delta: readonly [number, number]): void;
  rotateZone(zoneKey: string, rotY: number): void;
  addFixture(opts: FixtureOptions): string;  // 返回 fixtureId
  removeFixture(fixtureId: string): void;
  updateFixture(fixtureId: string, patch: Partial<Fixture> | (f: Fixture) => void): void;
  moveFixture(fixtureId: string, pos: readonly [number,number,number]): { autoUnbound: boolean };
  selectFixture(id: string | null): void;
  selectZone(key: string | null): void;
  lockField(fixtureId: string, fieldPath: string): void;
  applyScene(sceneKey: string): void;          // 登记平滑过渡
  applySceneInstant(sceneKey: string): void;   // 立即应用
}
```

要点：
- 用 `zustand/middleware` 的 `immer` 中间件：`create(immer((set, get) => ({...})))`。
- 所有改 project 的 action，内部调 `binding.ts` 的纯函数（它们用 `structuredClone`，与 immer 兼容）或直接用 immer draft 改。
- `addFixture` 用 `makeFixture` 生成实体后写入 `project.fixtures[id]`。
- `lockField`：用户每次手动改某字段都同步把字段路径加入 `lockedFields`（ADR-17 的关键——手动改 = 锁定）。
- 提供 `createInitialProject()`：一个含 1-2 个活动区 + 几盏灯的默认工程，供首屏展示。

### 2. `src/scene/sceneEngine.ts` — 补 `updateFixture` + `setFixtureLevel`
见「缺口 1 / 2」。新增 `getFixtureLevel(fixtureId)` 供过渡动画查询当前实况。

### 3. `src/scene/sceneController.ts` — 场景过渡动画（新建）
用 `sceneSystem.ts` 已有的 `applySmooth` / `sample` / `finishTransition`：
- `applyScene(key)`：调 `sceneSystem.applySmooth(key)` 拿到 `{from, to, durationMs}`，记录 `startedAt`。
- `tick(now)`（每帧被引擎渲染循环调用）：若过渡未结束，按 `easeInOut` 进度从 store 取对应灯的当前目标，逐帧写进 store 的 level 并 `engine.setFixtureLevel`；结束时 `finishTransition()` 落盘。
- 注意：过渡期间**逐帧更新的是 level（亮度）与 cct**，cct 要通过 `updateFixture` 改 `electrical.cct` 再重建（或引擎提供 `setFixtureCct` 直接改 light.color，避免每帧重建光源）。**优先给引擎加 `setFixtureCct(fixtureId, kelvin)`**（直接改 `light.color` + `cctToRGB`），比每帧重建光源高效得多。

### 4. `src/ui/` — React 面板组件（新建目录）
- `panels/ZonePanel.tsx`：活动区列表 + 新增（选类型下拉）+ 删除 + 重命名 + 改类型。
- `panels/FixturePanel.tsx`：选中灯的参数表单（位置 xyz / 姿态 pitch·yaw / 亮度 / 色温 K / 光通量 / 光束角）。**每个输入 onChange 都调 `updateFixture` + `lockField`。** 显示「配光为近似值」徽标（当 `photometric.ies` 有值或无 IES 解析时，按 `hasVerifiedIES` 判定）。

- `panels/IlluminancePanel.tsx`：每个活动区一行，用 `formatIlluminance` 输出（**红线标注不可省**）。
- `App.tsx` 重写：左侧 ZonePanel + FixturePanel，右侧 ScenePanel + IlluminancePanel，中间 canvas。移除所有 `getElementById`。
- 时间控制（现有 time/speed/shadow）保留，但改成 React 组件状态，调 `engine.setHour` 等。

样式：沿用 `index.html` 里已有的深色 `.overlay` / `.controls` 风格，做成可折叠侧栏面板。

### 5. `src/App.tsx` — store ↔ engine 同步（重写）

- 每次 project 变化，调 `calculateAllZones` 刷新照度（可放在 store action 里或单独 selector）。

## 红线（违反即返工）

- **照度红线**：所有 lx 展示必须经 `formatIlluminance`，末尾 DISCLAIMER 不可省。
- **配光近似红线**：无真实 IES 解析时，UI 必须标注「配光为近似值」。
- **架构红线**：业务层不得直接 `import { WebGLRenderer } from 'three'` 或 `three/webgpu`，只走 `src/render/backend.ts`。
- **导入红线**：不得引 `three/addons` 桶文件，按具体路径导入。
- **代码规范**：TypeScript strict，不逃逸 `any`，named export，camelCase 文件名。ESLint 0 error。
